## Champs de gestionnaire d'une fiche selon le rôle sur le périmètre (INC-13, PER-06)

- **Quoi** : `RecordForm` reçoit de la fiche (`RecordDetail`) le rôle de gestionnaire sur le
  périmètre de l'enregistrement, déjà calculé pour le statut et le verrouillage ; le rôle AD
  ne reste que le repli (formulaires de création, liste des périmètres non chargée). Les
  champs `managerOnly` d'une fiche suivent ainsi la même règle que l'API : case « Incident
  majeur », commentaire sur un conflit de calendrier d'un changement, champs de gestionnaire
  d'une déclaration réglementaire. Un test de l'interface couvre trois cas : User AD
  gestionnaire du périmètre de l'incident (case active), User AD sur un périmètre où il est
  User (grisée), Manager AD simple User du périmètre (grisée).
- **Pourquoi** : le rôle par périmètre prime sur le rôle AD (PER-03, ADR-0014 D4) ; l'écran
  grisait une décision que l'API autorisait, et inversement.
- **Fichiers** : `frontend/src/core/components/RecordForm.jsx`,
  `frontend/src/core/components/RecordDetail.jsx`,
  `frontend/src/core/components/RecordDetail.perimeter.test.jsx`
