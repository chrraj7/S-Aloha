## Sondes de santé de l'API (O1, partie 1)

- **Quoi** : `GET /health/live` répond 200 dès que le processus sert des requêtes ;
  `GET /health/ready` répond 200 si la base répond, 503 sinon (contrôle `DatabaseReady` :
  une connexion, sans paquet supplémentaire). Les deux routes sont anonymes et ne renvoient
  que l'état. Healthcheck du service `api` dans `docker-compose.yml`, par `bash` (l'image
  ASP.NET n'a ni `curl` ni `wget`), essayé contre l'API lancée sur une base jetable : code 0
  base démarrée, 1 base arrêtée. Tests d'API : les deux routes sans jeton, et la
  disponibilité en échec sur une base injoignable. O1 est soldé au plan d'action.
- **Pourquoi** : un orchestrateur ne pouvait savoir l'API prête qu'en appelant une route
  métier, qui exige un jeton.
