- **Quoi** :
  - **Documentation de la corrélation** : #381 a fusionné le code et les tests de la
    corrélation depuis la branche de travail, avant leur documentation. Celle-ci suit ici :
    TRI-05 à TRI-07 ✅, synthèse des pratiques, plan d'action, journal de la corrélation, note
    du journal des versions.
  - **Une seule proposition ouverte par champ** (OPT-14) : une valeur nouvelle remplace sur
    place la proposition ouverte du même champ, comme une ligne par champ dans l'encadré du
    tri. L'essai de bout en bout laissait sinon deux impacts ouverts sur un même incident :
    « Faible », par la criticité du service, puis « Élevé », par la panne probable.
  - **Notification d'une panne probable** : « Panne probable : 3 incidents ouverts sur le
    service Impression », sans répéter le nombre.
  - **Spécification rétablie** : le texte d'OPT-14 (valeur écartée non reproposée) et d'OPT-15
    (proposition périmée rafraîchie au recalcul), perdu à la fusion de #378, dont le code et
    les tests sont bien sur `main`.

  première), `ProbableOutagesTests` (texte de la notification). Essai de bout en bout, pile de
  démonstration, API et conteneur réels : trois incidents sur le service Impression, rejoints
  par un incident des données d'exemple créé dans l'heure, forment une panne de 4. Le bandeau
  est servi (depuis le plus ancien, parent proposé, déclaration majeure possible pour
  l'Admin), une seule notification part, l'impact Élevé est proposé.
