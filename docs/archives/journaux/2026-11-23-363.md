# 2026-11-23 — Socle des fonctionnalités optionnelles (F14 étape 1, OPT-01 à OPT-08)

<sub>[← Archives](../readme.md)</sub>

- **Quoi** : l'API connaît les trois fonctionnalités optionnelles (tri assisté des tickets,
  CMDB assistée, serveur MCP), contrôle la santé de leur conteneur (`Features:Url` et son
  jeton, `Mcp:Url`) et ses dépendances, et garde le choix de l'Admin. Administration ›
  Fonctionnalités optionnelles les montre (indisponible, coupée, activée) et les active ou
  les coupe, avec confirmation ; une activation sans conteneur, avec un jeton refusé ou une
  dépendance obligatoire manquante est refusée avec son motif ; chaque changement est
  tracé. `GET /api/features` donne aux écrans les seules clés activées ; une route marquée
  `[RequiresFeature]` répond 404 quand sa fonctionnalité est coupée. Un conteneur perdu
  laisse la fonctionnalité activée et la page Santé la signale « Dégradé ». Le journal
  d'audit porte une **origine** (« Saisie » par défaut), affichée, filtrée et exportée.
- **Pourquoi** : étape 1 du chantier F14 (#362), plan validé par le mainteneur le
  2026-11-23 ; elle débloque les étapes 2 (contrat avec le conteneur) et 6 (serveur MCP).
- **Preuve** : `OptionalFeaturesTests` (10 tests, conteneur factice) et 9 tests d'interface
  (`features.test.js`, `OptionalFeatures.test.jsx`, `History.origin.test.jsx`,
  `AuditLog.origin.test.jsx`), qui ne compilent pas sur `main` (code absent). Suites
  complètes vertes en local, nouveaux tests compris : API 415, interface 201. Deux
  attentes existantes suivent le changement : la ligne d'export d'ADM-31 finit par
  l'origine, et l'instantané OpenAPI gagne `FeatureView`.
- **Fichiers** : `backend/Core/Features/`, `backend/Core/Audit/AuditEntry.cs`,
  `backend/Core/Administration/AdminController.cs`, migration `OptionalFeatures`,
  `frontend/src/core/features.js`, `frontend/src/core/pages/admin/OptionalFeatures.jsx`
- **Documentation** : fonctionnalités optionnelles (OPT-01 à OPT-08 ✅, OPT-07 et OPT-08
