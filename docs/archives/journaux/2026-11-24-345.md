# 2026-11-24 — Sécurité : une ligne par point dans le tableau de durcissement (#345)

<sub>[← Archives](../readme.md)</sub>

- **Quoi** : dans `docs/reference/securite.md`, § « Points de durcissement avant
  production », les points `Secrets`, `LDAP` et `Transport` n'ont plus qu'une ligne chacun,
  celle qui est à jour (✅ S1 pour les secrets, ✅ S2 pour LDAPS et HTTPS). Les trois lignes
  d'origine, restées après S1 (#289) et S2 (#285), sont retirées.
- **Pourquoi** : chaque paire donnait deux états opposés pour un même point ; un exploitant
  pouvait croire LDAPS non pris en charge, ou chercher les secrets dans `docker-compose.yml`,
  qui les lit dans l'environnement depuis S1.
- **Preuve** : `docker-compose.yml` lit `POSTGRES_PASSWORD`, `JWT_KEY` et
  `DISCOVERY_VAULT_KEY` dans l'environnement ; `Ldap:CaCertificatePath` et
  `docker-compose.https.yml` existent sur `main`.
- **Fichiers** : `docs/reference/securite.md`
- **Documentation** : la ligne `Secrets` reprend sa place en tête du tableau. L'exception
  GHSA-fc5q-39xc-vjpf, que `scripts/check-audit-npm.py` signale sans objet, se retire avec
  le script, dans une PR d'outillage à part.
