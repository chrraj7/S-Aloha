# 2026-11-24 — Convention de nommage de la CMDB assistée, côté API (F14 étape 5a-4, CMA-04)

<sub>[← Archives](../readme.md)</sub>

- **Quoi** : la convention de nommage par type de CI, que la tâche Renommer transmet au modèle.
  - **Tenue** : `PUT /api/assisted-cmdb/naming/{ciType}` par un gestionnaire d'au moins un
    périmètre, comme les autres référentiels sans périmètre (PER-13) : une description (500
    caractères au plus) et jusqu'à cinq exemples d'une ligne ; type hors de la liste : 400. Une
    description vide retire la convention : Renommer ne s'applique plus à ce type.
  - **Lecture** : `GET /api/assisted-cmdb/naming` pour tous, dans l'ordre des types ; le
    conteneur lit `GET /internal/assisted-cmdb/naming`, au format que la tâche Renommer attend
    déjà (5a-3, #401).
  - **Coupée** : la CMDB assistée coupée, les routes n'existent pas (OPT-04).
- **Pourquoi** : 5a-4 de l'étape 5 du chantier F14 (#367). Avec elle, Renommer s'applique aux
  types qui ont leur convention. La page Paramétrage › Convention de nommage vient avec
  l'interface (5a-5).
- **Preuve** : `AssistedCmdbNamingTests` (404 coupée ; tenue par un gestionnaire, exemples
  dédoublonnés ; lecture pour tous dans l'ordre des types ; 403 à un simple utilisateur ;
  bornes ; lecture par le conteneur ; retrait par une description vide). Il ne compile pas sur
  `main`.
- **Fichiers** : `backend/Modules/ServiceConfigurationManagement/AssistedCmdb.cs`,
  `backend/Core/Data/AppDbContext.cs`, migration `NamingConventions`
- **Documentation** : CMDB assistée (CMA-04 en cours ; § 5), base de données
- **Commit** : #367
