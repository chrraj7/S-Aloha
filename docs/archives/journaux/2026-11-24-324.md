# 2026-11-24 — Changements : réécrire un changement Évalué efface les décisions du CAB (#324)

<sub>[← Archives](../readme.md)</sub>

- **Quoi** : un `PUT` qui change le type, le risque, les plans ou le créneau d'un changement
  Évalué efface ses décisions du CAB (`ChangeApprovals`) ; le changement reste Évalué et
  attend de nouveau deux approbations. Titre et description se modifient sans effet sur
  elles.
- **Pourquoi** : les décisions ne s'effaçaient qu'à l'entrée dans Évalué ; un changement
  Normal à risque Élevé pouvait être autorisé « CAB : A, B » sur des plans que A n'avait pas
  vus. Décision du mainteneur du 2026-11-24 (option A du dossier) : une approbation porte sur
  un contenu précis, comme l'autorisation simple (CHG-07) et les demandes (#257).
- **Preuve** : `ChangeGovernanceTests.CHG_20_reecrire_un_changement_evalue_efface_les_decisions_du_CAB`,
  rouge avant la correction (une décision restait comptée), vert après ; les 43 tests des
  changements passent.
- **Fichiers** : `backend/Modules/ChangeEnablement/Controllers/ChangesController.cs`
  (`BeforeSaveAsync`, `EvaluationChanged`), le test
- **Documentation** : `docs/reference/processus/habilitation-des-changements.md` (§ 3,
  CHG-20 et son scénario)
