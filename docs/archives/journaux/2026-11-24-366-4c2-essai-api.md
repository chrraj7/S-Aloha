# 2026-11-24 — Essai, compteurs et purge des traces du modèle de langage, côté API (F14 étape 4c-2, OPT-26, OPT-27)

<sub>[← Archives](../readme.md)</sub>

- **Quoi** : la part de l'API dans l'essai, et les compteurs des traces.
  - **Essai** (OPT-26) : `POST /api/admin/settings/language-model/test` (Admin) remet les
    réglages enregistrés, même désactivés, la CMDB assistée coupée comprise, au conteneur
    (`POST /language-model/test`, 4c-3). Le résultat se lit sans secret, comme ADM-63 : modèle
    joignable et durée, réponse non conforme et motif, délai, erreur, conteneur injoignable.
    L'API garde la trace de l'essai (`language-model` / `essai`).
  - **Appel d'essai** : `FeaturesClient` gagne un appel qu'un écran attend sans fonctionnalité
    activée, au délai du modèle (deux essais, plus 10 s) ; son client HTTP ne borne plus le
    délai lui-même, chaque appel le borne (2 s pour les écrans, OPT-16, inchangé).
  - **Compteurs** (OPT-27) : `GET …/language-model/usage?days=` (1 à 90 jours), par
    fonctionnalité et issue : nombre, durée moyenne, réponses écartées, dernier appel.
  - **Purge** : quotidienne, après 90 jours (`Features:LanguageModelCallRetentionDays`), avec
    celle du fil d'événements.
- **Pourquoi** : 4c-2 dans le découpage de 4c en quatre PR ; s'appuie sur la table des traces
  (4c-1, #396). La page suit (4c-4).
- **Preuve** : `LanguageModelEssayTests` (essai avec des réglages désactivés, échec motivé sans
  secret, conteneur absent, Admin seul ; compteurs sur 30 et 90 jours, purge à 90 jours). Ils
  ne compilent pas sur `main`.
- **Fichiers** : `backend/Core/Features/LanguageModel.cs`, `FeaturesClient.cs`, `FeatureEvents.cs`
- **Documentation** : fonctionnalités optionnelles (OPT-27 ✅, OPT-26 en cours ; § 6),
  exploitation, architecture
