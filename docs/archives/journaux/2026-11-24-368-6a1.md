# 2026-11-24 — Serveur MCP : jetons d'accès personnels côté API (MCP-03, MCP-04 ; #368 6a-1)

<sub>[← Archives](../readme.md)</sub>

- **Quoi** : table `PersonalTokens` (migration additive : empreinte SHA-256 seule, index unique,
  expiration, révocation, dernière utilisation, rôle et groupes relus). `PersonalTokenHandler`
  authentifie un « Bearer sat_… » sur `GET`/`HEAD` seulement, serveur MCP activé seulement ;
  l'identité est relue dans l'annuaire à la première requête puis toutes les 5 minutes (compte
  absent : 401 ; annuaire injoignable : 503). Un schéma de sélection (`Program.cs`) envoie un
  jeton personnel à ce gestionnaire et tout le reste au JWT de session. Routes
  `GET/POST /api/me/tokens`, `DELETE /api/me/tokens/{id}`, `GET /api/admin/tokens`,
  `DELETE /api/admin/tokens/{id}` (404 coupées) : nom requis, 1 à 90 jours (30 par défaut),
  5 actifs au plus, jeton rendu une seule fois.
- **Pourquoi** : étape 6 du chantier F14 (#368), sous-partie 6a découpée en 6a-1 (API) et
  6a-2 (pages), pour tenir 10 fichiers par PR.
- **Preuve** : `PersonalTokensTests` (création, affichage unique, empreinte, lecture seule,
  plafond, révocations, coupure ; rôle du moment relu au-delà de 5 minutes, 503, 401).
- **Fichiers** : `backend/Core/Auth/PersonalTokens.cs`, `PersonalTokensController.cs`,
  `backend/Core/Data/AppDbContext.cs`, la migration, `backend/Program.cs`, le test
- **Documentation** : `docs/reference/serveur-mcp.md` (MCP-03 côté API, MCP-04, MCP-09 en
  partie) ; la note `changelog.d/` viendra avec la page (6a-2)
