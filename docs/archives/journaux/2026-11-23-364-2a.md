# 2026-11-23 — Port interne, jeton du conteneur et fil d'événements (F14 étape 2a, OPT-10 à OPT-12)

<sub>[← Archives](../readme.md)</sub>

- **Quoi** : l'API écoute aussi sur un **port interne** (8081, `ASPNETCORE_HTTP_PORTS=8080;8081`
  dans l'image), jamais publié : les routes `/internal/…` n'existent que là, et ce port ne
  sert rien d'autre que ces routes et les sondes. Elles exigent le **jeton du conteneur**
  `features` (`Features:Token`, 32 caractères au moins, comparé en temps constant ; un jeton
  d'utilisateur n'y ouvre rien). Un **fil d'événements** (`FeatureEvents`) inscrit, après
  chaque enregistrement réussi, ce qu'une fonctionnalité activée lit : incidents créés,
  modifiés, résolus, supprimés pour le tri assisté ; CI, actifs du sas et tâches de
  découverte terminées pour la CMDB assistée. Le conteneur le lit par
  `GET /internal/events?after=` ; le fil garde 7 jours et signale par `gap` un curseur qui a
  perdu des événements purgés.
- **Pourquoi** : sous-partie 2a de l'étape 2 du chantier F14 (#364) ; le conteneur
  `features` (2c) et les propositions (2b) s'y appuient. Sans fonctionnalité qui le lit,
  aucun événement n'est inscrit : le fil ne grossit pas pour rien.
- **Preuve** : `InternalContractTests` (5 tests : port, jeton, fonctionnalités activées,
  fil et curseur, absence d'inscription, purge et `gap`), qui ne compilent pas sur `main`.
  Le jeton du conteneur factice des tests passe à 32 caractères.
- **Fichiers** : `backend/Core/Features/InternalContract.cs`,
  `backend/Core/Features/FeatureEvents.cs`, `backend/Program.cs`, `backend/Dockerfile`,
  migration `FeatureEvents`
- **Documentation** : fonctionnalités optionnelles (OPT-10 à OPT-12 ✅, contrat du fil),
  sécurité (port 8081, policy du conteneur), exploitation (`Features:InternalPort`,
  `Features:EventRetentionDays`), architecture, base de données, synthèse des pratiques,
  plan d'action
- **Commit** : #364
